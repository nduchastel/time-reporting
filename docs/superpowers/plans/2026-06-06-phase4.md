# Phase 4 Execution Plan — Beta Hardening, Admin, Auth, Worksites

> **Status:** SHIPPED — 2026-06-07. All tasks built across stacked branches (setup → security → admin-credentials → worksites → panels → observability → install), each with tests and a green suite. The *what/why* lives in [`../../phase4-plan.md`](../../phase4-plan.md); the auth model lives in [`../../security.md`](../../security.md). Body frozen; see Changelog at the end.

> **For agentic workers:** implement task-by-task in the order below. Tasks within a group are mostly independent unless a dependency is noted. Every task lands with tests and leaves `npm run test:all` green. Extend `backend/tests/fakes/fakeSupabase.js` whenever a route uses a new query shape (it throws `not implemented:` otherwise — see `../../testing.md`).

**Goal:** Make the app safe and complete enough for a real-customer beta — security hardening, error monitoring, an admin portal + full user management, the temporary-credential/forced-first-login model, per-worker panel visibility, worksite management, PWA install, and onboarding guides.

**Tech already in place:** Node 22 / Express 5 (ESM), React 19 + Vite + Tailwind, Supabase, `bcryptjs`, `jsonwebtoken`, Vitest + Supertest + Playwright. New deps expected: `express-rate-limit`, an error-tracking SDK (provider chosen at execution).

## Group A — Security & access hardening

- [x] **A1 (Task 1) — Ownership auth on `GET /api/time-cards`** (closes `TODO(Task 10)` in `backend/src/routes/timeCards.js`).
  - Add `requireAuth()` to the route. For `role==='worker'`, force `workerId = req.user.sub` (ignore any client-supplied `workerId`). Managers/admins may pass any `workerId`.
  - Frontend: `WorkerHistory.jsx` fetches via `apiFetch` with the token (no client id); `lib/auth.js` already attaches the bearer token.
  - **Tests:** worker cannot read another worker's cards (own only); manager can read any; missing token → 401. Existing `tests/integration/timeCards.test.js` updated.
- [x] **A2 (Task 2) — Rate limiting on `/api/auth/*`.**
  - Add `express-rate-limit`; apply to `worker/login` + `manager/login` in `backend/src/routes/auth.js` (per-IP window, 429 on exceed). Keep the constant-time bcrypt compare.
  - **Tests:** N failed logins → 429; a success under the limit still works.
- [x] **A3 (Task 3) — CORS lockdown.** In `backend/src/server.js` replace `app.use(cors())` with `cors({ origin: <ALLOWED_ORIGINS split> })`; default to Vercel domain(s) + localhost for dev. **Tests:** disallowed origin rejected, allowed passes.
- [x] **A4 (Task 4) — JWT TTL role-based.** In `backend/src/services/authService.js`, make `issueToken` accept a role/TTL (worker `7d`, manager/admin `24h`) instead of the flat `30d`; update callers in `auth.js`. Decide re-auth UX (re-login on expiry; no refresh tokens this phase). **Tests:** token `exp` matches role; expired token rejected (extend existing unit test).
- [x] **A5 (Task 5) — Supabase RLS.** Add RLS policies (in the migration or a follow-up SQL) on `time_cards`, `workers`, `worksites` mirroring the server-side role checks (defense-in-depth — the API holds the keys). Verify the service-role path still works for admin ops. Document policies in `database-schema.md`. (Offline-testability is limited; smoke-verify against a real instance in CI if available.)

## Group C (backend) — Admin user-management API

- [x] **Task 8 — `backend/src/routes/admin.js`**, mounted at `/api/admin` in `server.js`, guarded by `requireAuth(['admin'])`:
  - `GET /users` — list across roles (no secret fields).
  - `POST /users` — create worker/manager/admin with a **temporary** secret; set `must_change_credential=true`. Manager/admin: `username` + temp `password`; worker: `phone` + temp `pin`. Hash via `hashSecret`.
  - `PATCH /users/:id` — edit profile, **change role**, enable/disable (`status`).
  - `POST /users/:id/reset-credential` — set a new temp PIN/password, re-set `must_change_credential=true`.
  - `DELETE /users/:id` — hard delete with guards: **cannot delete self**, **cannot delete the last active admin**.
  - Reuse validation + error mapping (409 unique, 404 not-found) like `routes/manager.js`. Extend `fakeSupabase`.
  - **Tests (`tests/integration/admin.test.js`):** manager/worker forbidden (403); create each role; role change; reset re-arms first-login; can't-delete-self; can't-delete-last-admin.

## Group F (backend) — Credential lifecycle

- [x] **Task 15 — Forced first-login change.**

  - Login responses (`worker/login`, `manager/login`) include `must_change_credential` so the client can gate.
  - **Tests:** freshly-created and freshly-reset users are flagged; flag clears after change; new secret required on next login.
